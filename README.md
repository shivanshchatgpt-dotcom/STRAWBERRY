# Chat Memory Tree

A local-first desktop app that turns saved AI chats, coding discussions, notes,
and imported text files into a personal knowledge tree. Every saved chat gets a
deterministic, rule-based brief generated **entirely on your machine** — no AI
services, no network calls, no telemetry.

- **Platform:** Windows, macOS, Linux (Tauri v2)
- **Stack:** Rust + React + TypeScript + Vite + Zustand + SQLite (FTS5)
- **Storage:** one SQLite database plus plain text/markdown/JSON files inside
  your OS app-data directory. Everything stays offline.

```
Home
├── School                 <- example only; you create any roots you want
│   ├── Physics
│   │   ├── Gravity Chat
│   │   └── Motion Chat
│   └── Chemistry
├── Biology
└── Vibe Coding
    ├── ChatGPT Ideas
    └── Claude Verify
```

Roots are never hardcoded. First launch shows an empty state prompting you to
create your first index.

## Features

- Unlimited custom root indexes; nested folders; chats at any level
- Create chats by pasting text, or import `.txt` / `.md` / `.json`
- Local rule-based brief generator (Rust): preserves fenced code blocks,
  commands, errors, URLs, decisions, action items; strips filler/duplicates
- Chat reader tabs: Brief / Original / Code / Errors / Commands / Decisions /
  Metadata
- Breadcrumb navigation, expandable sidebar tree, keyboard-friendly controls
- Global + scoped search (SQLite FTS5 with automatic LIKE fallback)
- Delete confirmations everywhere data is destroyed; files removed from disk
- Original chat files are never modified after creation

## Prerequisites

1. **Rust** (stable): https://rustup.rs
2. **Node.js** >= 18 and npm
3. Platform webview dependencies:
   - **Windows:** WebView2 (preinstalled on Win10/11 recent builds; Tauri
     prompts/installs otherwise). MSVC Build Tools via Visual Studio.
   - **macOS:** Xcode Command Line Tools (`xcode-select --install`)
   - **Linux (Debian/Ubuntu):**
     ```bash
     sudo apt update
     sudo apt install libwebkit2gtk-4.1-dev build-essential curl wget file \
       libxdo-dev libssl-dev libayatana-appindicator3-dev librsvg2-dev
     ```
   - **Linux (Arch):** `sudo pacman -S webkit2gtk-4.1 base-devel`

## Icons

Binary icon files are generated by `scripts/generate_icons.py` (pure Python
stdlib, no dependencies). They ship pre-generated under `src-tauri/icons/`. If
they are ever missing, regenerate before building:

```bash
npm run icons        # requires python3
```

This writes `32x32.png`, `128x128.png`, `128x128@2x.png`, `icon.png`,
`icon.ico`, and `icon.icns`.

## Install & run (development)

```bash
npm install
npm run tauri dev
```

First run compiles ~400 Rust crates; subsequent runs are fast.
The dev server binds strictly to http://localhost:1420.

## Production build

```bash
npm run tauri build
```

Artifacts land in `src-tauri/target/release/bundle/`
(`.msi`/`.exe` on Windows, `.dmg`/`.app` on macOS, `.deb`/`.AppImage`/`.rpm`
on Linux).

## Type-check frontend without building

```bash
npm run check:ts
```

## Where is my data?

| Item | Location |
| --- | --- |
| Database | `<app_data_dir>/app.db` |
| Raw chat files | `<app_data_dir>/files/<root_id>/<node_id>/<chat_id>.raw.txt` |
| Briefs | `<app_data_dir>/files/<root_id>/<node_id>/<chat_id>.brief.md` |
| Metadata | `<app_data_dir>/files/<root_id>/<node_id>/<chat_id>.meta.json` |

`<app_data_dir>` resolves to:

- Windows: `%APPDATA%\com.local.chatmemorytree`
- macOS: `~/Library/Application Support/com.local.chatmemorytree`
- Linux: `~/.local/share/com.local.chatmemorytree`

File paths use stable UUIDs, so renaming roots/folders/chats never breaks
storage. The in-app Metadata tab shows exact paths for the open chat.

## Troubleshooting

- **Port 1420 busy** — kill the stale process (`lsof -ti :1420 | xargs kill`)
  or restart; Vite uses `strictPort` so it fails fast instead of drifting.
- **Linux build error about `webkit2gtk-4.1`** — install the packages listed
  under Prerequisites; Ubuntu 22.04+ provides the `-4.1` variants.
- **Windows build error about WebView2** — install the Evergreen WebView2
  Runtime from Microsoft, then rebuild.
- **Search returns nothing on unusual setups** — the app falls back to
  case-insensitive LIKE search automatically if FTS5 is unavailable; both paths
  cover titles, first idea, tags, and brief text.
- **Icons missing during `tauri build`** — run `npm run icons`.
- **Long chats feel slow in Original tab** — content renders in chunks; press
  “Load more” repeatedly. The Brief tab always renders instantly.

## Known limitations

- Brief generation is intentionally heuristic/rule-based (no AI). Quality
  depends on how clearly roles (`User:` / `Assistant:`) and structure appear in
  the source text.
- Original chat bodies live on disk only (not in FTS); search covers title,
  first idea, tags, and brief text.
- Single window, no multi-tab chat reading.
- JSON import expects a top-level array of `{role, content}` messages (the
  common export shape); other JSON is saved verbatim as a custom import.
