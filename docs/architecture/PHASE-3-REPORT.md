## Phase 3A — Canonical Event Model

### What Was Implemented

Created `strawberry-core/src/canonical_event.rs` — the unified event representation that all event sources normalize into.

### Design

The model supports 6 distinct roles:
- **Raw** — immutable occurrence, append-only
- **Observation** — normalized/filtered, deduped
- **Memory** — user-visible, revisable
- **Insight** — derived, regenerable
- **Task** — actionable, lifecycle-owned
- **Action** — taken step, audited

### Fields

| Field | Purpose |
|---|---|
| `id` | UUID unique identifier |
| `role` | Event role (raw/observation/memory/insight/task/action) |
| `event_type` | Namespaced type (e.g. "clipboard.captured") |
| `source` | Producer subsystem |
| `source_version` | Adapter version for future migration |
| `reference` | Link to domain object (not full data) |
| `actor` | User/System/Agent(id) |
| `occurred_at_ms` | When it happened |
| `created_at_ms` | When recorded |
| `project_id` | Project context |
| `session_id` | Session context |
| `payload` | Small inline JSON metadata |
| `privacy_level` | public/sensitive/secret |
| `dedupe_key` | Deduplication key |
| `retention` | short/medium/permanent/user_managed |
| `confidence` | 0.0–1.0 |
| `provenance` | How this event was derived |

## Phase 3C — Multi-Subscriber EventBus

### What Was Implemented

Extended the existing `EventBus` in `src-tauri/src/autonomous/event.rs` with multi-subscriber support while preserving the legacy `drain` API.

### Architecture

```
Observer → bus.publish(ev)
              ├── Fan out to all Subscribers (non-blocking, channel full = drop)
              └── Queue for legacy drain() consumers
```

### Key Design Decisions

- Subscribers receive clones via `std::sync::mpsc::sync_channel(256)` — bounded, non-blocking
- If a subscriber falls behind, events are dropped (no unbounded memory)
- `subscribe()` returns `(Subscriber, Receiver)` — subscriber can be unsubscribed
- `unsubscribe(id)` removes a subscriber
- Legacy `drain()` API unchanged — AutonomyRuntime continues working
- `subscriber_count()` for diagnostics

### Tests: 3

- `subscriber_receives_events` — publish → subscriber gets it
- `unsubscribe_removes_subscriber` — cleanup works
- `multiple_subscribers_independent` — two subscribers both get events
